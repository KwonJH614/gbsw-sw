# 개발계획서 (P2)

> HoopPath — 2단계 확장 개발 계획
> React 19 + TypeScript | Spring Boot 3 + Java | MySQL | 2026년 4월

## 1. 기술 스택

| 구분 | 기술 | 비고 |
|------|------|------|
| Frontend | React 19 + TypeScript | Vite, P1과 동일 |
| Backend | Spring Boot 3 + Java | Gradle, P1과 동일 |
| Database | MySQL 8 | 기존 스키마 확장 (마이그레이션) |
| ORM | JPA / Hibernate | |

| 파일 저장 | — | 2단계 내에서는 URL 직접 입력. S3 도입은 3단계 |

## 2. 시스템 아키텍처 변화

### 인가 흐름 (신규)

```
요청 → JwtFilter (토큰 파싱 → SecurityContext 세팅)
     → Controller 진입 전 @PreAuthorize("hasRole('INSTRUCTOR')") 체크
     → 권한 부족 시 403 FORBIDDEN 응답
```

P1은 로그인/비로그인만 구분했지만, P2는 role 단위 접근 제어가 필요하다.

### 역할별 라우팅 (프론트)

```
AppRouter
├── 공개 라우트 (/, /courses, /courses/:id, /login, /register)
├── 학생 전용 (/dashboard, /lessons/:id/play)       → RoleRoute role="STUDENT"
├── 강사 전용 (/instructor/*)                        → RoleRoute role="INSTRUCTOR"
└── 어드민 전용 (/admin/*)                          → RoleRoute role="ADMIN"
```

## 3. 개발 일정

전체 3주 예상 (P1과 동일 템포)

| 주차 | 작업 |
|------|------|
| 1주차 | Phase 0 (역할 체계 세팅) + Phase 1 (강사 신청/승인) |
| 2주차 | Phase 2 (강의/레슨 CRUD) + Phase 3 (수강생 대시보드) |
| 3주차 | Phase 4 (어드민 콘솔) + Phase 5 (QA) |

### Phase별 요약

| Phase | 목표 | 핵심 산출물 |
|-------|------|------------|
| 0 | 역할 체계 기반 세팅 | `@RequireRole`, `RoleRoute`, role 포함 JWT, DB 마이그레이션 |
| 1 | 강사 신청 / 어드민 승인 | `instructor_applications` 테이블, 신청/승인 API, 신청 페이지 |
| 2 | 강의 · 레슨 CRUD | POST·PATCH·DELETE /courses, /lessons, 강사 콘솔 페이지 |
| 3 | 수강생 대시보드 | `/dashboard/overview` 집계 API, 위젯 4종 |
| 4 | 어드민 콘솔 | 강사 신청 / 회원 / 강의 관리 3화면 |
| 5 | QA & 통합 테스트 | 역할 접근 제어 전수 확인, 시나리오 테스트 |

## 4. 브랜치 전략

P1과 동일하게 유지하되, P2 전용 베이스 브랜치를 둔다.

```
main          → P1 완료 시점 (유지)
p2-develop    → P2 통합 개발 브랜치 (★ 신규)
feature/p2-*  → P2 기능별 (feature/p2-role, feature/p2-course-crud 등)
```

- PR은 `p2-develop`으로만 올림
- P2 완성 후 `main`에 병합

## 6. 리스크 및 대응

| 리스크 | 대응 방안 |
|--------|----------|
| 역할 체크 누락으로 권한 우회 | 서버는 `@PreAuthorize` 필수, 프론트 `RoleRoute`는 UX용으로 명시 |
| 강사가 자기 것 아닌 강의 수정 시도 | Service 레벨에서 `course.instructorId == 로그인 사용자` 검증 |
| 대시보드 쿼리 N+1 | 집계 쿼리 1개로 묶고 DTO Projection으로 조회 |
| 강사 신청 스팸 | 사용자당 PENDING 신청 1개만 허용 (unique 제약 or 서비스 체크) |
| 기존 users 테이블 role 확장 | 기존 데이터는 `STUDENT` 기본값, 마이그레이션 스크립트로 ADMIN 1개 지정 |
