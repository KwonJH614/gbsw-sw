## 2. 시스템 아키텍처

### 인가 흐름

```
요청 → JwtFilter (토큰 파싱 → CustomUserDetails → SecurityContext 세팅)
     → Controller 진입 전 @PreAuthorize("hasRole('INSTRUCTOR')") 체크
     → 권한 부족 시 AccessDeniedException → 403 ROLE_REQUIRED 응답
```

`@AuthenticationPrincipal CustomUserDetails`로 userId 추출.
`Long`으로 직접 주입하면 null이므로 반드시 `CustomUserDetails` 사용.

### 역할별 레이아웃 (프론트)

```
AppRouter
├── Layout (헤더+푸터)
│   ├── 공개 라우트 (/, /courses, /roadmaps, /login, /register, /403)
│   └── PrivateRoute
│       ├── /dashboard            → StudentDashboardPage
│       ├── /instructor/apply     → InstructorApplyPage
│       ├── /my                   → MyPage
│       └── /courses/:id/lessons/:lessonId
├── InstructorLayout (사이드바)  → INSTRUCTOR 전용
│   ├── /instructor               → InstructorDashboardPage
│   ├── /instructor/courses/new   → CourseFormPage
│   ├── /instructor/courses/:id/edit
│   └── /instructor/courses/:id/lessons
└── AdminLayout (사이드바)       → ADMIN 전용
    ├── /admin                    → AdminDashboardPage
    ├── /admin/users              → UserManagePage
    ├── /admin/courses            → AdminCoursePage
    ├── /admin/applications       → AdminInstructorApprovalPage
    └── /admin/audit-logs         → AuditLogPage
```

### role 반영 흐름

```
앱 로드 → App.tsx AuthInit → GET /users/me → authStore.user 갱신
→ 헤더·레이아웃 즉시 반영 (재로그인 불필요)
```

## 6. 리스크 및 대응

| 리스크 | 대응 방안 |
|--------|----------|
| `@AuthenticationPrincipal Long`으로 null 주입 | `CustomUserDetails`로 받고 `.getId()` 추출 — 전체 P2 컨트롤러 통일 완료 |
| 승인 후 role 미반영 (구 JWT 유지) | App.tsx AuthInit에서 `/users/me` 호출로 즉시 갱신, 재로그인 불필요 |
| 강사 승인 시 instructors 레코드 미생성 | `approve()` 트랜잭션 내 `Instructor.create()` 동시 저장 완료 |
| 강의 삭제 시 수강생 존재 검증 | `enrollmentRepository.existsByCourseId()` 체크 후 409 반환 |
| 강사 신청 스팸 | `existsByUserIdAndStatus(PENDING)` 체크 후 409 APPLICATION_PENDING |
| BOM 문자로 TSX 파일 깨짐 | fix_tsx.js로 UTF-8 BOM 없이 재작성
