# 아키텍처 (P2)

> HoopPath — P2 시스템 아키텍처
> 역할 확장 + 강사 콘솔 + 학생 대시보드 | 2026년 4월

---

## 전체 구조 개요

```
┌─────────────────────────────────────────────────────────┐
│                클라이언트 (React SPA)                    │
│  Pages → Layout(역할별) → Components → Hooks → API      │
│  App.tsx AuthInit → GET /users/me → authStore 갱신       │
└──────────────────────┬──────────────────────────────────┘
                       │ HTTP REST (Bearer Token)
┌──────────────────────▼──────────────────────────────────┐
│            Spring Boot API 서버                          │
│  Controller (@PreAuthorize + CustomUserDetails)          │
│  → Service → Repository                                  │
│  └─ Global: JwtFilter / ExceptionHandler                │
└──────────┬──────────────────────────┬───────────────────┘
           │ JPA                      │ HTTP
    ┌──────▼──────┐           ┌───────▼───────┐
    │  MySQL 8    │           │  Vimeo API    │
    │  + 신규     │           └───────────────┘
    │  테이블 2종  │
    └─────────────┘
```

P1 대비 달라진 점:
- JWT claims에 `role` 포함 → 서버·프론트 동일 기준 권한 판단
- `CustomUserDetails`로 principal 세팅 → `@AuthenticationPrincipal CustomUserDetails`로 userId 추출
- `@PreAuthorize`로 역할 체크 일원화
- `InstructorLayout` / `AdminLayout` — 역할별 사이드바 레이아웃
- `App.tsx AuthInit` — 앱 로드 시 `/users/me` 호출로 role 즉시 반영

#### Global 모듈 (P2 변경)

| 클래스 | 변경 내용 |
|--------|-----------|
| `JwtFilter` | `CustomUserDetails`로 principal 세팅 |
| `CustomUserDetails` | `id / email / password / authorities` 보유, `ROLE_` 접두사 부여 |
| `GlobalExceptionHandler` | `AccessDeniedException → 403 ROLE_REQUIRED` 핸들러 추가 |
| `P2ErrorCode` | 6개 에러코드 추가 |
| `BusinessException` | `status` 필드 (P1 원본과 통일) + `of(P2ErrorCode)` 팩토리 |

#### @AuthenticationPrincipal 사용 규칙

```java
// ❌ null 주입됨
public ResponseEntity<?> method(@AuthenticationPrincipal Long userId) { ... }

// ✅ P2 표준
public ResponseEntity<?> method(@AuthenticationPrincipal CustomUserDetails userDetails) {
    Long userId = userDetails.getId();
    ...
}
```

## 3. 데이터 흐름

### A — 강사 신청 → 승인 → 콘솔 진입

```
InstructorApplyPage → POST /instructor-applications
  → PENDING 레코드 생성 (PENDING 1개 제한)

AdminInstructorApprovalPage → POST /instructor-applications/{id}/approve
  → [트랜잭션]
      app.status = APPROVED
      user.role = INSTRUCTOR
      instructors 레코드 생성 (bio/career 복사)
      audit_log 기록

InstructorApplyPage "강사 콘솔로 이동" 버튼
  → GET /users/me → authStore role 갱신
  → navigate('/instructor')
```

### B — 강의 생성

```
CourseFormPage → POST /courses
  → @PreAuthorize("hasRole('INSTRUCTOR')")
  → instructorRepository.findByUserId(userId)  ← instructors 레코드 필요
  → Course.create(instructor, ...) → 저장
  → InstructorDashboardPage로 이동
```

### C — 수강생 대시보드

```
StudentDashboardPage mount
  → GET /dashboard/overview
    → stats: enrollments/reviews 집계 (JDBC 단일 쿼리)
    → recentCourses: progress 상위 3개 JOIN courses
    → roadmapProgress: 수강 기반 JOIN roadmap_courses
  → 5분 인메모리 캐시 (useDashboard)
```

### D — 어드민 행위 감사 로그

```
AdminUserController.changeRole / suspend
AdminCourseController.setVisibility
InstructorApplicationController.approve / reject
  → 각 서비스에서 auditLogService.record(adminId, action, targetType, targetId, memo)
  → REQUIRES_NEW 트랜잭션 — 메인 트랜잭션 실패해도 로그는 남김
```
