# 요구사항 명세서 (P2)

> HoopPath — 2단계 확장 기능 요구사항
> 역할 체계 + 강사 콘솔 + 학생 대시보드 + 어드민 | 2026년 4월

---

## 우선순위 기준

| 등급 | 의미 |
|------|------|
| 필수 | P2 완료 판정에 반드시 포함 |
| 권장 | 일정 여유 시 포함 |

> P1 요구사항(U/R/C/E/L/RV)은 그대로 유지된다. 이 문서는 **P2에서 추가·변경되는 것만** 기술한다.

---

## 1. 역할 (Role)

| ID | 요구사항 | 우선순위 | 상태 | 상세 조건 |
|----|----------|----------|------|----------|
| RL-01 | role 3단계 도입 | 필수 | ✅ | STUDENT(기본) / INSTRUCTOR / ADMIN |
| RL-02 | JWT payload에 role 포함 | 필수 | ✅ | 로그인 시 accessToken claims에 role 주입 |
| RL-03 | 서버 역할 기반 접근 제어 | 필수 | ✅ | `@PreAuthorize` + `CustomUserDetails` |
| RL-04 | 프론트 역할 기반 레이아웃 | 필수 | ✅ | InstructorLayout / AdminLayout — 사이드바 포함 |
| RL-05 | 헤더 메뉴 분기 | 필수 | ✅ | STUDENT: 대시보드·강사신청, INSTRUCTOR: 내강의관리, ADMIN: 어드민 |
| RL-06 | 앱 초기화 시 role 즉시 반영 | 필수 | ✅ | App.tsx AuthInit → GET /users/me (재로그인 불필요) |

## 2. 강사 신청 (Instructor Application)

| ID | 요구사항 | 우선순위 | 상태 | 상세 조건 |
|----|----------|----------|------|----------|
| IA-01 | 강사 신청서 작성 | 필수 | ✅ | STUDENT만 신청 가능, 경력·소개·샘플 영상 URL 입력 |
| IA-02 | 중복 신청 차단 | 필수 | ✅ | PENDING 상태 신청이 이미 있으면 409 APPLICATION_PENDING |
| IA-03 | 내 신청 상태 조회 | 필수 | ✅ | PENDING / APPROVED / REJECTED 상태 표시 |
| IA-04 | 어드민 신청 목록 조회 | 필수 | ✅ | ADMIN 전용, `?status=PENDING` 필터 |
| IA-05 | 어드민 승인 | 필수 | ✅ | user.role → INSTRUCTOR + instructors 레코드 자동 생성 (트랜잭션) |
| IA-06 | 어드민 거절 | 필수 | ✅ | 사유 텍스트 첨부, 재신청 허용 |

## 7. 비기능 요구사항 (P2)

| 구분 | 내용 | 상태 |
|------|------|------|
| 인가 | 모든 쓰기 API는 `@PreAuthorize` 필수, `CustomUserDetails`로 userId 추출 | ✅ |
| 무결성 | 강의 삭제 시 수강 존재 검증 (409), 레슨 삭제 시 진도 처리 | ✅ |
| role 즉시 반영 | 앱 초기화 시 `/users/me` 호출로 DB role 갱신 (JWT 만료 불필요) | ✅ |
| 시드 데이터 | 어드민 계정 1개 — 비밀번호 bcrypt 해시 후 SQL 직접 삽입 | ✅ |
| 감사 로그 | 어드민 행위(권한 변경·정지·강의 중지·신청 처리) audit 기록 | ✅ |

## 8. 기존 요구사항 변경사항

| 변경 대상 | 내용 |
|-----------|------|
| U-01 회원가입 | role은 자동 STUDENT (입력 불가) |
| C-01 강의 목록 조회 | isVisible=true인 것만 노출 |
| E-01 수강 신청 | 강사 본인은 본인 강의에 수강 신청 불가 (403) |
