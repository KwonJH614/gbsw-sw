# 요구사항 명세서 (P2)

> HoopPath — 2단계 확장 기능 요구사항
> 역할 체계 + 강사 콘솔 + 학생 대시보드 + 어드민 | 2026년 4월

---

## 우선순위 기준

| 등급 | 의미 |
|------|------|
| 필수 | P2 완료 판정에 반드시 포함 |
| 권장 | 일정 여유 시 포함 |

> P1 요구사항(U/R/C/E/L/RV)은 그대로 유지된다. 이 문서는 **P2에서 추가·변경되는 것만** 기술한다.

---

## 1. 역할 (Role)

| ID | 요구사항 | 우선순위 | 상세 조건 |
|----|----------|----------|----------|
| RL-01 | role 3단계 도입 | 필수 | STUDENT(기본) / INSTRUCTOR / ADMIN 세 가지 |
| RL-02 | JWT payload에 role 포함 | 필수 | 로그인 시 accessToken claims에 role 주입 |
| RL-03 | 서버 역할 기반 접근 제어 | 필수 | `@PreAuthorize("hasRole('...')")` 로 엔드포인트 단위 보호 |
| RL-04 | 프론트 역할 기반 라우팅 | 필수 | `RoleRoute` 로 권한 없을 시 403 페이지 또는 리다이렉트 |
| RL-05 | 헤더 메뉴 분기 | 필수 | role에 따라 "강사 콘솔" / "어드민" / "대시보드" 버튼 노출 |

---

## 2. 강사 신청 (Instructor Application)

| ID | 요구사항 | 우선순위 | 상세 조건 |
|----|----------|----------|----------|
| IA-01 | 강사 신청서 작성 | 필수 | STUDENT만 신청 가능, 경력·소개·샘플 영상 URL 입력 |
| IA-02 | 중복 신청 차단 | 필수 | PENDING 상태 신청이 이미 있으면 409 반환 |
| IA-03 | 내 신청 상태 조회 | 필수 | PENDING / APPROVED / REJECTED 중 어느 상태인지 |
| IA-04 | 어드민 신청 목록 조회 | 필수 | ADMIN 전용, 상태 필터링 가능 |
| IA-05 | 어드민 승인 | 필수 | 해당 user.role → INSTRUCTOR 변경 + instructors 프로필 생성 |
| IA-06 | 어드민 거절 | 필수 | 사유 텍스트 첨부 가능, 재신청 허용 |

## 3. 강의 관리 (Course Management) — 강사

| ID | 요구사항 | 우선순위 | 상세 조건 |
|----|----------|----------|----------|
| CM-01 | 강의 생성 | 필수 | INSTRUCTOR만 가능, 제목·설명·썸네일URL·level |
| CM-02 | 내 강의 수정 | 필수 | 본인이 만든 강의만, 모든 필드 변경 가능 |
| CM-03 | 내 강의 삭제 | 필수 | 수강생이 없을 때만 삭제, 있으면 `DELETE_BLOCKED` |
| CM-04 | 내 강의 목록 조회 | 필수 | 강사 콘솔용, 수강생 수 · 평균 별점 포함 |
| CM-05 | 내 강의 수강생 조회 | 권장 | 강의별 수강생 이름·진도율·수강일 목록 |

---

## 4. 레슨 관리 (Lesson Management) — 강사

| ID | 요구사항 | 우선순위 | 상세 조건 |
|----|----------|----------|----------|
| LM-01 | 레슨 생성 | 필수 | 본인 강의에만, 제목·영상URL·duration 입력 |
| LM-02 | 레슨 수정 | 필수 | 본인 강의의 레슨만 |
| LM-03 | 레슨 삭제 | 필수 | 해당 레슨에 진도 기록 있으면 경고 후 확인, 강제 삭제는 진도도 함께 제거 |
| LM-04 | 레슨 순서 변경 | 필수 | order_index 일괄 재정렬 PATCH |

## 5. 수강생 대시보드 (Student Dashboard)

| ID | 요구사항 | 우선순위 | 상세 조건 |
|----|----------|----------|----------|
| DB-01 | 누적 지표 4개 | 필수 | 수강 중·완료 강의 수, 총 학습 시간(분), 작성한 리뷰 수 |
| DB-02 | 최근 본 강의 | 필수 | 마지막 진도 업데이트 기준 상위 3개, 이어보기 버튼 |
| DB-03 | 로드맵 달성률 목록 | 필수 | 내가 1개 이상 수강한 로드맵만 노출, 완료율 내림차순 |
| DB-04 | 이번 주 활동 피드 | 권장 | 시청·완료·리뷰 작성 이벤트 최근 10건 |
| DB-05 | 대시보드 → 마이페이지 구분 | 필수 | `/dashboard` 는 시각화 중심, `/my` 는 CRUD(수강 취소 등) 중심 |

## 6. 어드민 콘솔 (Admin)

| ID | 요구사항 | 우선순위 | 상세 조건 |
|----|----------|----------|----------|
| AD-01 | 회원 목록 조회 | 필수 | 이메일·닉네임 검색, role·상태 필터 |
| AD-02 | 회원 권한 변경 | 필수 | STUDENT ↔ INSTRUCTOR ↔ ADMIN, 본인 계정 강등은 차단 |
| AD-03 | 회원 정지 | 권장 | is_suspended 플래그 토글, 정지 시 로그인 차단 |
| AD-04 | 강사 신청 관리 | 필수 | IA-04/05/06과 동일 |
| AD-05 | 강의 노출 중지 | 권장 | is_visible 플래그 토글, 중지 시 목록·검색에서 제외 |

## 7. 비기능 요구사항 (P2 추가)

| 구분 | 내용 |
|------|------|
| 인가 | 모든 쓰기 API는 서버 `@PreAuthorize` 필수, 프론트 라우트 체크는 UX용 |
| 무결성 | 강의 삭제 시 수강 존재 검증, 레슨 삭제 시 진도 처리 규칙 명시 |
| 일관성 | role 변경 시 JWT 즉시 만료는 X, 다음 토큰 재발급 시 반영 |
| 시드 데이터 | 어드민 계정 1개 고정 생성 (`admin@hooppath.local`) |
| 로그 | 어드민 행위(권한 변경·정지·강의 중지)는 audit 로그 남김 (권장) |

## 8. 기존 요구사항 변경사항

| 변경 대상 | 내용 |
|-----------|------|
| U-01 회원가입 | role은 자동 STUDENT (입력 불가) |
| C-01 강의 목록 조회 | is_visible=true 인 것만 노출 (어드민 제외) |
| C-02 강의 상세 조회 | 강의 소유 강사의 nickname·bio 포함 (기존 유지) |
| E-01 수강 신청 | 강사 본인은 본인 강의에 수강 신청 불가 (403) |
